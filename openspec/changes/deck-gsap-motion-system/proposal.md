# Proposal: Deck GSAP Motion System
Generated by: cm-start + cm-brainstorm-idea
Date: 2026-05-26

## Why we're doing this

The deck already has a strong Operator Briefing System, but the motion layer was split across Reveal transitions, CSS fragment animations, CSS keyframes and a cover-only GSAP timeline. That makes future animation work harder to reason about and risks adding spectacle without presenter value.

## 9 Windows Summary

| Level | Past | Present | Future |
|-------|------|---------|--------|
| Super-system | Slides were mostly static with Reveal transitions. | Audience expects live, polished, tool-like demos. | Motion should make the agent workflow feel concrete. |
| System | Animation lived in slide-specific CSS. | Cover uses GSAP; other slides use CSS fragments/keyframes. | A small GSAP controller coordinates enter, fragment and hero moments. |
| Sub-system | Bars, cards and diagrams animated independently. | Some animations overlap in responsibility. | Motion uses transforms/opacity, reduced-motion fallback and cleanup on slide leave. |

## Options Evaluated

### Option A: Tune Existing CSS Only

Keep all animations in CSS and refine timings.

- Effort: Small
- Risk: Low
- Trade-off: Cleaner than today, but no runtime control or special sequencing.

### Option B: DeckMotion GSAP Controller

Add a centralized GSAP controller for slide enter, fragment reveal and a few special highlight moments.

- Effort: Medium
- Risk: Medium-low
- Trade-off: Best balance of polish, maintainability and presenter control.

### Option C: Cinematic Animation Pass

Make every slide heavily choreographed with more 3D, scan and continuous ambient motion.

- Effort: Large
- Risk: High
- Trade-off: More impressive at first glance, but likely distracting for an internal briefing.

## Recommendation

Choose Option B.

It keeps the deck calm, but adds memorable motion where it teaches the concept: survey evidence animates into proof, workflow gets a visible execution runner, and demo media gets a proof scan.

4. Kill loops and generated nodes when leaving a slide.
