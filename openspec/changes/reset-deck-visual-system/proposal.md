## Why We're Doing This

### Qualified Problem

**For:** Sea technical/operations audience and the presenter.
**Who:** need a practical AI Agent Playbook that is easy to follow during a live sharing session.
**The:** current Reveal.js deck has accumulated several visual directions in one large `style.css`.
**That:** causes later edits to break contrast, spacing and hierarchy.
**Unlike:** the previous patch-by-patch approach, this reset uses the existing slide content as source of truth and rebuilds one cohesive visual layer.
**Our approach:** keep the 13-slide narrative and HTML content, delete the stale `DESIGN.md`, then replace the visual system with a simpler operations-briefing style.

### Root Causes

1. **Technical:** `style.css` contains multiple generations of overrides, so later rules fight earlier rules.
2. **Product:** the deck is an internal practical briefing, but parts drifted into dashboard/landing-page styling.
3. **Design:** the audience needs readable hierarchy and calm proof points, while the deck had too many heavy cards, glows and mixed palettes.

### Impact If Not Addressed

- Presenter confidence drops because slides look unstable.
- The Ocean USB Builder demo feels less credible if the surrounding deck looks noisy.
- Future edits keep breaking unrelated slides.

## Options Evaluated

### Option A: Fresh Briefing CSS Reset

**Approach:** Replace `style.css` with a fresh cohesive visual layer while preserving `index.html` content and slide order.
**Philosophy:** Tech-first plus design repair.
**Effort:** M.
**Risk:** Medium.
**Pros:** Removes accumulated CSS conflicts; fastest route to a stable deck-wide visual.
**Cons:** Requires broad visual QA because every slide is affected.

### Option B: Add One More Override Layer

**Approach:** Keep current CSS and append a final rescue section.
**Philosophy:** Quick-win.
**Effort:** S.
**Risk:** Medium-high.
**Pros:** Fast and easy to rollback.
**Cons:** Continues the exact pattern that caused the design drift.

### Option C: Rebuild HTML And CSS Together

**Approach:** Redesign slide markup and CSS as a new deck implementation.
**Philosophy:** Design-first.
**Effort:** L.
**Risk:** High.
**Pros:** Maximum control.
**Cons:** Too much content churn; likely to disturb speaker notes and verified flow.

## Recommendation

**Choose Option A: Fresh Briefing CSS Reset.**

Why:

1. It directly addresses the CSS conflict root cause.
2. It preserves the 13-slide narrative, speaker notes and Ocean USB Builder scope.
3. It gives future edits a smaller and more understandable style foundation.

## Visual Direction

**Name:** Operator Briefing System.

**Tone:** calm, technical, evidence-led and presentation-ready.

**Rules:**

- Light content slides by default.
- Dark navy only for the cover and Q&A closeout.
- Sea navy is authority, Sea blue is system/progress, Shopee orange is proof/risk/action.
- Cards are simple objects, not nested decorative shells.
- Motion is presenter-controlled and subtle.
- The most memorable visual should be the arc: survey signal -> agent workflow -> safety -> Ocean USB Builder -> judgment.
